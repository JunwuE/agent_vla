当前入口：[操作目录](../skills/INDEX.md)。旧实现每个源码/契约哈希生成一个新 `recovery-*` ID，

- 4 类有明确起始状态的关门操作关联 9 个原有参数化版本；149 个未整理的现场恢复版本仍可通过旧 ID

- `search_skills` 每项返回一个操作，`list_skill_versions` 展开其不同入口条件、参数与历史结果。
- 相同技能换参数直接调用；执行结果追加到原版本的 runs，不复制成新技能。同一会话重试还复用已导入的工作区版本。
- 逻辑修订继承语义名称和来源；导入/修改保留能力、前置条件、完成条件与参数契约。
- 新建 `write_program` 必须给出语义名称、适用状态及不能复用的理由；已有名称使用直接调用或导入修订。

集中参数与感知检查点，应是下一步 Code Policy 重构的目标。当前技能仍用 `run(ctx)`，
不能声称已与 RAX 完全一致，也不能由目录整理推断新 seed 成功率或耗时改善。

## 当前两条复用路径

适用的技能直接运行：

`search_skills → read_skill → check_skill → submit_intervention(kind=code, skill_id, skill_version, parameters)`

需要适配的候选程序：

`search_skills(include_candidates=true) → read_skill → import_skill_program → patch_program / patch_program_batch → check_program → submit_intervention(kind=code, program_version, parameters)`

`import_skill_program` 从当前 Episode 的不可变库快照复制准确源码，不执行动作、不晋级技能。
每个工作区版本保存 `origin_skill`，补丁继承来源；后续候选证据也保留来源。旧文件不会被覆盖。
只读审核期间不能创建或修改程序。

`write_program` 和 `patch_program` 支持 `parameter_schema`、`parameter_sources`。
程序通过 `ctx.parameters` 读取参数，宿主在执行前验证类型、范围和必填字段；禁止外部 schema 引用。
补丁默认继承参数契约，显式新 schema 形成新的版本。执行过的候选保留契约，后续 Episode 可直接按技能 ID 调用。
所有动作仍经过 Harness，完整子任务的原生验证器决定是否完成。

## 什么可以复用

可以复用测量、坐标变换、短程反馈、阶段检查和已经有运行证据的操作逻辑。
新场景的图像区域、目标几何、接触状态必须重新测量。参数契约并不证明输入的感知结果正确。

早期两个成功候选只在特定中间状态通过验证：一个要求起始步数 1335，另一个要求 1326，
后者还读取旧的历史帧来拟合轨迹。不能直接删掉保护或把旧坐标作为新布局目标。
适配时应改为当前状态的可观测前置条件，必要时改写测量阶段，再执行完整程序验证。
尚未验证通过的源码分支、失败探索和单次偶然成功不应标为普适技能。

## 减少重复推理

- 同任务经验优先于长笔记中的偶然关键词；最佳任务匹配内兼顾代码恢复成功、无代码接管的成功和失败，避免恢复案例挤走正常 VLA 执行证据。
- 技能检索的前五项为同任务已成功程序保留一个位置，避免大量包含更多关键词的失败变体挤走所有成功例子；未知任务前缀不推断同任务，不改变适用条件或执行权限。
- 搜索结果返回阶段和运行摘要，`read_skill` 展开完整源码及历史测量；原生验证结论、失败原因、参数契约和证据位置不丢失。
- 当前上下文已有相关经验时先读它，换阶段或证据不足才重新检索；已读过的接口和稳定几何约定不逐轮重读。
- 启用 `planner.deduplicate_experiences` 后，同一线程中不变的历史记录只发送引用；`read_experience` 可展开全文，线程重启或上下文压缩后重新发送。
- 明确失败阶段后局部修改，普通反馈循环留在程序内运行。
- `patch_program_batch` 对同一版本的多个修改原子校验，任一不匹配则不生成部分更新；一次最多 16 个不重叠修改。
- `fit_geometry` 在提交程序前对当前观测得到的同坐标系点做只读拟合，报告平面/圆残差和退化；数值拟合不证明点对应、接触或成功。
- 计时分别记录初始规划、运行审核、恢复规划/修订、程序执行和总 Episode 时间。

2026-10-30 验证：全量测试 `185 passed in 17.51s`。覆盖原样导入、来源继承、只读权限、参数约束、
工作进程实际参数化执行、后续候选契约保留。该测试数字不是新 seed 的任务成功率。

后续补充可配置的观测导出预算及 Flora 输入准备优化，全量测试 `187 passed in 18.07s`。
64 帧输入准备从 3.40–3.57 秒降到 1.23 秒；解码后的全部图像像素及输入元数据完全一致。
该计时仅覆盖 CPU 准备，不含 Flora 推理；256 MiB 导出预算仅用于本轮较长恢复程序配置，默认值仍为 64 MiB。

跨 seed 的实际调用、轨迹配对和耗时在 [实验报告](../runs/toaster-cross-seed-20261030/cross-seed-results.md) 持续记录。

补充直接技能调用的修订链路：直接调用时，宿主同样将来源和参数契约保存到工作区；失败后可以直接 patch 并继续传参数。
调用另一技能时不继承前一个无关程序的来源。实际工作进程回归覆盖参数化技能首次未完成、局部修改后完成，
全量测试 `188 passed in 17.84s`。

## 真实探索暴露的接口开销

round15 seed9 在第 325 步暂停，导入旧候选并修改两次，但在提交执行前耗尽 48 次工具调用预算。
该轮失败保留；导入/修改不是动作成功示范。日志中有重复的目标选择、深度查询和完整源码读取。

据此增加 `measure_targets`：一次对最多 8 个当前图像区域返回选择来源及对应深度几何，保持同一观测快照、
整数框坐标、标定和可靠性检查。避免为每个区域反复调用两个工具并返回整张叠加图。
`bbox` 的 schema 显式使用整数 `items`，仍拒绝字符串、布尔值、非整数及错误长度。

工具结果接近预算时附带剩余调用数；暂停规划的预算耗尽可在同一总超时和总模型调用预算内有限续接，
保留工作区与暂停状态，没有提交完成的方案不会执行。只读运行审核不自动重开。
这不是自动增加 Episode 动作预算。新回归覆盖批量结果等价、过期区域拒绝、冻结审核快照、
预算续接保留版本与有限终止；全量测试 `192 passed in 19.48s`。

实际连续修订还发现顶层 `eef_control_pose` 曾保留最初接管时的状态，虽然观测窗口、Memory 与运行时工具已更新。
Astra 在日志中识别了旧时间戳并重新观察。现改为每次代码修订统一重建 planner context，包含当前末端位姿、
控制器、能力与绑定；回归测试验证执行动作后的各字段同一时刻，全量 `192 passed in 25.09s`。
round16 使用已加载的 v5，后续进程才应用该 v6 修复；不将它作为已证实的视觉跟踪失败原因。

v7 进一步读取技能的后续 runs.jsonl，保留最近的成功、失败和近期记录，完整原始证据不丢弃；
当前 Episode 快照不因新运行变化，candidate 不自动晋级。经验中的代码哈希可解析为当前机器人快照下的
准确技能 ID/版本，多个参数契约共享源码时保留全部候选引用。对应回归 194 项通过。

round17 发现 Planner 的 capabilities 与代码 ctx.capabilities 返回字段不一致，造成一次无动作拒绝。
v8 将机器人能力、控制器标定、当前末端位姿和观测步数统一到共享快照；工作进程回归覆盖动作前后当前性。
全量 `195 passed in 26.02s`；该修复用于后续运行，round17 保留原 v7。
