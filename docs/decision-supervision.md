# Decision：五时刻三视角与规则复核

2026-10-29 更新。当前开发入口是 `configs/close_toaster_dev.yaml`，通用真实环境配置
`configs/robocasa.yaml` 与 `DecisionConfig` 默认值也使用三视角历史。
旧实验的 `suite15.yaml` / `atomic_low_calls.yaml` 保留其显式主视角配置；已有 runs 不修改。

## 输入

选择距当前 10、5、2、0.5、0 秒的五个历史时刻，每个时刻取 left / right / wrist，共最多 15 张独立图片。
按照“时刻 → 相机”排列，`frame_map` 明确标记相机、控制步、仿真时间和图片索引。
开始执行或重试初期不复制图片凑数；不跨尝试选帧。缺少配置要求的相机时转 ESCALATE，不静默减少视角。
数值继续使用精简摘要，包含六个近期动作样本、近 2/10 秒运动统计、任务阶段、尝试状态、模型评估和规则证据。
原始精度日志不变。`shadow_decision.py` 已改为使用同一历史采样和摘要逻辑。

多视角历史有助于看到腕部接触变化、主视角遮挡及目标相对运动；代价是更多视觉输入和可能的冗余。
更多图片不保证更准确：移动相机、背景变化及不相关画面也可能干扰判断。

## 五类标准

实际英文判据在 `src/vla_agent/decision_criteria.py`，版本 `robot-supervision-v2`。
每次请求保存实际判据、提示、图片数量和版本，便于重放。

| 类别 | 要求的判断依据 | 容易误判的边界 |
|---|---|---|
| KEEP | 当前目标/阶段合理，没有具体需要 Astra 审核的证据 | 未完成、首次接近、正常撤回、短暂保持、一个视角遮挡，不直接算失败 |
| REFINE | 目标和前置条件仍成立，出现可纠正的执行或指导偏差 | 不是“必须细化语言”；Astra 可以保持指令、使用代码，或确认无需动作干预 |
| SWITCH | 完整当前可执行子任务具有满足完成条件的证据 | 内部阶段完成、夹爪闭合、达到位姿或高 reward 都不足以直接切换 |
| REPLAN | 目标、任务依赖或剩余顺序与场景冲突 | 一次空抓、局部接触失败、几次尝试失败，不等于计划失效 |
| ESCALATE | 存在值得审核的重要不确定性、冲突或无法解释的持续异常 | 不把所有信息缺失都升级；普通未完成阶段可能仍应 KEEP |

所有非 KEEP 都先交 Astra 只读审核；类别不直接决定工具、不直接暂停 VLA。
类别间仍可能模糊，当前没有通过人工标签验证这些判据的准确率。
现有概率规则不变：开发配置 `keep_threshold=0.0`、`min_margin=0.05`；阈值待校准。

## 规则的合适边界

保留两种用途：

- 确定性执行约束：非法/越界动作、过期控制权、执行异常和预算由固定宿主处理，不依赖模型解释。
- 可疑现象：提供可追溯证据并触发复核，不把它升级成确定失败、任务完成或 VLA 技能缺失。

本次替换了旧的“最近 10 个观测中末端位置极小变化”检测。20 Hz 下旧窗口约 0.45 秒，
且只看平移，容易忽略转腕、底座与夹爪运动。

当前低运动检测要求：

| 项目 | 开发默认值 |
|---|---|
| 连续观测窗口 | 至少 4 秒**仿真执行时间**，至少 10 个观测；20 Hz 时通常为 81 帧 |
| 末端、底座位置变化范围 | 各不超过 2 mm |
| 末端、底座旋转变化 | 各不超过 0.02 rad，正确处理 q 与 -q 的等价性 |
| 夹爪关节变化范围 | 不超过 1 mm |
| 命令证据 | 完整连续 VLA 实测/命令记录；保存运动通道幅值超过 0.05 的命令比例 |
| 冷却 | 同类规则复核间隔至少 4 秒；普通周期/事件复核仍独立运行 |
| 开关 | `runtime.stagnation_enabled`，可关闭以做消融 |

所有检测使用未舍入数据，并检查整段轨迹的变化范围；往返运动不能因为净位移接近零就算静止。
不跨尝试/阶段边界拼历史，不把 Code Policy 执行、缺失记录或暂停等待当成 VLA 停滞。

输出叫 `sustained_low_motion`，附原始范围、阈值、时间/步数、命令比例和 `failure_confirmed=false`。
它只安排一次 Decision 检查。Decision 可以在看到正常保持或任务仍推进的证据后返回 KEEP。
正常握持、等待物体运动或维持接触也可能被规则触发，所以不能据此硬判失败。
即使非零命令比例很高，归一化控制量也不能直接等同于预期物理位移。

若 Decision 持续 KEEP，已有的每 150 步 Astra 只读审核仍提供另一条检查途径，并受总预算约束。
本版没有加入“静止 N 秒强制 Code Policy”“失败 N 次判定 VLA 无能力”或“阶段超时自动 SWITCH”。
规则触发也有误报和推理成本，阈值是可调开发值，并非已经校准的物理边界。

## 实测与限制

同一张 H100 80GB、同一 d3-flash 固定版本、同一新版判据，对 OpenDrawer baseline
第 200、400 步的相同五时刻历史分别构造 7 图和 15 图请求。每个请求预热 2 次，测量 5 次。

| 输入 | token（两个窗口） | 热调用中位数（合并十次计时） |
|---|---|---:|
| 五张主视角 + 当前两个补充视角 | 3370 / 3396 | 182.6 ms |
| 五时刻 × 三视角 | 4143 / 4181 | 259.0 ms |

本次约增加 76.5 ms（41.9%）。计时包含本地模型的请求准备、图像处理、执行和概率输出，
不包含 HTTP、客户端图片编码、加载和预热；不是完整监督循环时延，也不是纯 GPU forward。
两种输入在这两个窗口都返回 KEEP。没有独立标签，不能据此声称新输入改善了准确率。
报告与复现命令见 [本轮记录](../runs/decision-15view-20261029/README.md)。

下一轮质量评估应覆盖正常保持、正常接近、空抓、脱离接触、持续受阻、完整子任务结束等片段，
分别标注当时是否需要审核；比较漏判、无效审核、执行中断和调用成本，不能直接使用模型自身输出作标签。
